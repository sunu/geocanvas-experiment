# Plan 022: code footnote v2, and "Show output on…" in the right-click menu

## Context

Code cells (plans/plan-021.md, built) put their output on other objects. Today each follower shows a full footnote per
code layer, which is noisy on a busy board, and `code.show` is reachable only from the agent or the console. The user
wants:

1. **One quiet summary line per object** ("‹/› 2 layers generated by code", plus a flag only when something is
   behind). Expand it to list each generated element. **Hovering an element highlights it** (the layer on the map,
   the object, its cell and the arrow). Click an element to open its details (code, state, edit, run).
2. **Hover or click a feature on the map** (while the map is edited or in focus) to open that layer's details in the
   footnote, with the feature outlined.
3. **"Show output on…" in the right-click menu of a code cell**, with a picker of the board's maps (and other objects
   that can show the output) and "New map" / "New sticky note" / "New image".

Decisions from the user: map hover means a feature on the map (deck.gl picking); the collapsed line is always shown.

## 1. Local emphasis (new, generic): `apps/web/src/canvas/emphasis.ts`

A local, never-synced store of object ids to emphasize, in the pattern of `canvas/loading.ts` (Map + listeners +
hook): `emphasize(key, ids)`, `clearEmphasis(key)`, `useEmphasized(id)`, `useEmphasizedIds()`.

- `ObjectView.tsx` adds class `is-emphasized` when its id is emphasized. CSS: an outline in `--canvas-accent` at about
  half strength, square and flat (canvas rules). It is not the selection outline.
- `Links.tsx` draws a link as `on` when either end is emphasized (same highlight as for the selection).
- Users: the footnote rows (the cell and the follower), the menu picker (the candidate object).

## 2. Code focus (new): `apps/web/src/code/focus.ts`

A local store of the code element in focus: `{ objectId, layerId?, cellId, pinned }`.

- `hover(element | undefined)`: from a footnote row or a map feature. It is cleared on leave.
- `pin(element | undefined)`: from a click (row or feature). It stays until the next click elsewhere or Esc.
- `useCodeFocus(objectId)` gives the element for one object (the pinned one wins over the hovered one).
- It also drives the emphasis: the follower and the cell (`emphasize('code', [objectId, cellId])`).

## 3. Footnote v2: `apps/web/src/code/Footnote.tsx` (rework)

- `sourcesOf` stays, and gives the elements of one object.
- **Collapsed line**, always shown:
  - "‹/› Generated by code · <cell title>" for one element
  - "‹/› N layers generated by code" for a map with several
  - An amber flag only when elements are behind: "1 run failed", "1 out of date", "1 not run". This counts the
    `followerState` results.
- **Expanded** (click the line): one row per element, with the layer title (or "this note"), the cell title and a
  state chip.
  - Row `onPointerEnter` → `hover`, `onPointerLeave` → `hover(undefined)`.
  - Row click → `pin` and open its details. The details are the current `Note` body: state text, `Code` (edit, run),
    Go to cell, Remove layer / Unlink. Only one is open at a time.
- **Driven by the map:** when `useCodeFocus(object.id)` gives an element, the footnote expands and opens that row. A
  hover opens it while the pointer is there; a pin keeps it open.
- Keep `stateText`, `RunError`, `CodeSource` and `useRunCell` as they are (`code/cell.tsx`).

## 4. The map: picking and highlight

`apps/web/src/map/layers.ts`, `deckLayers(states, opts?: { highlight?: string })`:

- **Code layers** (the recipe has `from`; add `from` to `LayerState` from the recipe) get `pickable: true`,
  `autoHighlight: true` (deck.gl outlines the hovered feature) and `highlightColor` from the canvas accent.
- **With `highlight` set:** that layer gets a 3 px line and a stronger fill, and the other feature layers get
  opacity × 0.35. Rasters and tiles stay as they are.

`apps/web/src/map/MapObject.tsx`:

- Pass `highlight = useCodeFocus(o.id)?.layerId` to `deckLayers` in the existing `setProps` effect (line ~346).
- On the `MapboxOverlay`, add `onHover` and `onClick`. They map the picked deck layer id (`layer-<id>`) back to the
  map layer, and when it has `from`, call `hover` / `pin` with `{ objectId: o.id, layerId, cellId: from }`. Clicks
  pin only when no drawing or scenario tool is active (the existing click handler at line ~253 keeps priority). A
  click on empty map clears the pin.
- Picking works only while the map has the pointer (edited or in focus). That is how maps work now. Snapshots (maps
  that are not live) show no highlight.

## 5. "Show output on…" in the right-click menu

**Op change, `packages/plugins/src/code.ts`:** `code.show` takes either `on` (an existing object) or `new: true`
(exactly one; zod refine).

- `new` adds the default follower for the output kind: `NEW_FOLLOWER` in `codeOutput.ts`, which maps `geo.features`
  to map, `image.png` to image, and `text` and `number` to sticky.
- The new object goes at the cell's right (x + w + 24, same y) with its type's default size. It uses an id made in
  `prepare`, then the existing `planShow` (a link, or a layer and the person's map view fitted).
- One transaction, so one undo step removes the new object and the link.
- Table and JSON outputs have no follower: `new` fails with "A table shows only in its cell".

**Menu, `apps/web/src/code/CodeMenu.tsx` (new), imported by `canvas/ObjectMenu.tsx`.** The Add to report submenu
already does the same, by importing `reports/reports`. It is shown when the selection is exactly one code cell.

- If the output kind has followers: a submenu "Show output on":
  - The board's objects whose type accepts the kind (`ACCEPTS`), named `name ?? <type title>`, numbered when names
    repeat ("Map 2").
  - A check and disabled for those that already show the cell (`followersOf`).
  - Each item's `onPointerEnter` emphasizes that object (key `menu`), and the emphasis clears when the menu closes.
  - A separator, then "New map" (or "New sticky note" / "New image").
  - Each item runs `code.show` with `beginGesture` and reports through `notify`.
- No output yet: the item is disabled with "Run it first". A table or JSON: disabled with "Shown only in its cell".
- Also "Run" (the `code.run` op as in the cell) in the same menu, since it's there.

## Verification

- `npm test`:
  - `code.show` with `new`: a map for features (layer `from`, view fitted, one undo removes both), a sticky for a
    number, a failure for a table, a failure when both `on` and `new` are given.
  - `deckLayers`: only `from` layers are pickable; `highlight` dims the others (apps/web/test/layers.test.ts).
- `npm run typecheck`, `npm run build`.
- Browser (Playwright against the local hub in `extras/jupyterhub/`, as before):
  1. A map with two code layers shows one line, "2 layers generated by code". Expand it; hovering a row gives the cell
     and the map `is-emphasized`, highlights the arrow, and dims the other layer on the live map.
  2. Break one cell: the line shows "1 run failed".
  3. Double-click the map, move the pointer over the buffer polygon: the footnote opens that layer's row. Click: it
     stays open after the pointer leaves. Esc closes it.
  4. Right-click a cell → Show output on → hover "Map 2" (it is emphasized) → click: the layer appears. "New map" adds
     a map at the cell's right, fitted to the features. ⌘Z removes it.
  5. Right-click a table cell: "Shown only in its cell" (disabled).

## Status (2026-10-30)

Built and tested in Chrome against a local JupyterHub: one summary line per object with flags, rows that point out
the element, its cell and their arrow, details opened by a row click or by a feature hovered or clicked on the map (Esc
lets go), the focused layer drawn stronger, and "Show output on" with the board's objects and a new one.

Changes from the plan:

- A row's hover only points things out; its details open on a click. A feature hovered on the map opens them. This
  keeps details from opening and closing as the pointer crosses the list.
- A map that already shows a cell stays a live entry in the menu (checked; choosing it says so), so that hovering it
  still points it out.
